# CareBridge Production Deployment Guide

This guide describes how to deploy CareBridge as a secure, production-grade healthcare coordination and referral system.

---

## 1. Production Architecture Overview

```
[Users / Clinicians]
        │ HTTPS (Port 443 with TLS 1.3)
        ▼
  ┌───────────┐
  │   Nginx   │ (SSL Termination, Rate Limiting, Gzip, Security Headers)
  └─────┬─────┘
        ├──────────────────────────┐
        │ Static SPA (/dist)       │ API Proxy (/api/*)
        ▼                          ▼
[React Single-Page App]    [Node.js Backend (Port 5000)]
                                   │
                      ┌────────────┴────────────┐
                      ▼                         ▼
               [MongoDB Database]        [Python ML Microservice (Port 8000)]
```

---

## 2. Demo Mode vs. Production Mode

All synthetic shortcuts and demo personas have been disabled:
- **Demo Logins Removed**: The "Demo Logins" tab and pre-filled synthetic test personas are completely removed.
- **Server Guard Enforced**: If `DEMO_MODE=true` is ever passed in production, `backend/src/server.js` throws a fatal security exception and refuses to boot.
- **Real Authentication**: All users log in via verified email and password.
- **Staff Onboarding**: Doctors, Nurses, Hospital Admins, and Platform Reviewers are onboarded via cryptographic invite codes generated by system administrators.
- **Patient Registration**: Patients self-register via the public registration screen (`/register`).

## 3. Production Environment Variables

Create `backend/.env.production` (or inject via your cloud secrets manager):

```env
# Application Environment
NODE_ENV=production
DEMO_MODE=false
PORT=5000

# Security Secrets (Must be 64+ character random strings)
JWT_SECRET=YOUR_SECURE_RANDOM_256_BIT_SECRET_KEY
JWT_EXPIRES_IN=8h

# Database (MongoDB Atlas Replica Set or self-hosted MongoDB)
MONGODB_URI=mongodb+srv://<db_user>:<db_pass>@<cluster>.mongodb.net/carebridge_prod?retryWrites=true&w=majority

# Host & Domains
FRONTEND_URL=https://carebridge.yourdomain.com
CORS_ORIGIN=https://carebridge.yourdomain.com
COOKIE_SECURE=true

# Python ML Microservice
ML_SERVICE_URL=http://ml-service:8000
```

## 4. Deployment Option A: Multi-Container Docker Compose (Recommended)

CareBridge includes a complete Docker configuration ready for deployment on any VPS (AWS EC2, DigitalOcean, Hetzner, etc.):

### Step 1: Clone the repository on your server
```bash
git clone https://github.com/your-org/carebridge.git
cd carebridge
```

### Step 2: Configure environment secrets
```bash
cp .env.example backend/.env
# Edit backend/.env with your production values
```

### Step 3: Launch with Docker Compose
```bash
docker compose up -d --build
```

### Step 4: Verify service health
```bash
docker compose ps
curl http://localhost:5000/api/health
```

---

## 5. Deployment Option B: Standalone Node.js + Static Build

If deploying to a single server without Docker:

### Step 1: Build the React frontend
```bash
npm ci --prefix frontend
npm run build --prefix frontend
```
*(The backend is already configured to automatically serve `frontend/dist` as static assets on port 5000).*

### Step 2: Install backend production dependencies
```bash
npm ci --prefix backend --only=production
```

### Step 3: Run with PM2 Process Manager
```bash
npm install -g pm2
NODE_ENV=production DEMO_MODE=false pm2 start backend/src/server.js --name "carebridge-api"
pm2 save
pm2 startup
```

## 6. Staff Onboarding & Initializing First Admin

Because public self-registration is restricted to patients, staff members (Hospital Admins, Doctors, Nurses) register using administrative invite codes:

```bash
# Generate an invite code for a Hospital Administrator:
node backend/src/scripts/generateInviteCode.js --role=hospital_admin --hospitalId=<HOSPITAL_ID>

# Generate an invite code for a Doctor:
node backend/src/scripts/generateInviteCode.js --role=doctor --hospitalId=<HOSPITAL_ID>
```

Staff members can then open the portal, click **"Register"**, check **"I have an official staff invite code"**, and create their credentials.

## 7. SSL & HTTPS Setup with Nginx & Certbot

Point your domain DNS (e.g., `A` record) to your server IP, then issue a Let's Encrypt certificate:

```bash
sudo apt update
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d carebridge.yourdomain.com
```

## 8. Backup & Data Security Checklist

1. **Database Backups**:
   Schedule daily encrypted MongoDB dumps:
   ```bash
   mongodump --uri="$MONGODB_URI" --archive=/backups/carebridge_$(date +%F).gz --gzip
   ```
2. **Encrypted Record Storage**:
   Ensure `backend/storage/records` is mapped to an encrypted filesystem volume or cloud object store (AWS S3 with SSE-KMS).
3. **Audit Log Retention**:
   The `auditlogs` MongoDB collection retains all access decisions, patient views, and triage actions for regulatory compliance.
