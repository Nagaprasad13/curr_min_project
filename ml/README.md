# CareBridge ML Clinical Decision Support Module

> **MANDATORY CLINICAL & RESEARCH DISCLAIMER**  
> **Research Prototype Only.** All outputs generated by this module (triage urgency suggestions, condition risk probabilities, and specialty mappings) are intended solely as **clinical decision support for a licensed medical practitioner to review**. They **DO NOT** constitute clinical diagnoses, automated admissions, or treatment directives. Models were trained on public benchmark cohorts (e.g., MIMIC-IV-ED Demo, Pima, Cleveland, ILPD) and **have NOT been validated on Tamil Nadu patient populations**. Standard emergency clinical evaluation supersedes all automated outputs.

---

## 1. Overview & Architectural Role

The CareBridge ML module enhances the referral platform by transforming raw patient intake parameters (vital signs, triage presentation, routine lab values) into actionable referral recommendations:
1. **Triage Severity Suggestion:** Predicts emergency acuity to prioritize referral dispatch.
2. **Multi-Condition Screening:** Computes calibrated risk probabilities across 5 chronic/acute conditions, with threshold-based flagging tuned for high clinical sensitivity ($\ge 90\%$).
3. **Rule-Based Emergency Safety Guard:** Bypasses probabilistic models to immediately escalate critical red flags (e.g., hypertensive crisis, acute stroke signs, unstable chest pain).
4. **Knowledge-Base Specialty Mapping:** Maps flagged conditions and symptoms deterministically to clinical specialties and required hospital equipment.
5. **Decision & Urgency Fusion:** Merges triage, conditions, and red flags into a unified recommended referral urgency (`emergency`, `urgent`, or `routine`), requiring explicit doctor review and confirmation.

## 2. Key Technical Design Decisions

### 2.1 Single Triage Task (Binary High vs. Lower Acuity)
- **Decision:** Emergency Department acuity is modeled as a binary classification task: Emergency Severity Index (ESI) 1 & 2 (*Immediate / Emergent resuscitation*) versus ESI 3, 4, 5 (*Urgent / Less Urgent / Non-urgent*).
- **Rationale:** Binary triage aligns directly with referral dispatch needs: identifying patients requiring immediate high-tier resuscitation versus those suitable for urgent or routine transfer. Multi-class 5-tier classification on small cohorts introduces extreme class imbalance and calibration noise without practical referral utility.

### 2.2 Separate Calibrated Models per Condition
- **Decision:** Rather than training a single black-box multi-label neural network, 5 independent calibrated classifiers were trained (Diabetes, Heart Disease, Liver Disease, Chronic Kidney Disease, Hypothyroid), complemented by 2 rule-based clinical screeners (Anemia, Hypertension).
- **Rationale:** 
  1. *Clinical Reality:* Patients rarely arrive with all lab tests completed. Separate models evaluate only the tests present, returning `"insufficient_data"` for unmeasured panels without failing the entire assessment.
  2. *Auditability & Interpretability:* Each disease model exposes clear feature contributions (e.g., serum creatinine, hemoglobin) and can be audited independently by medical sub-specialists.
  3. *Independent Threshold Tuning:* Clinical risk tolerance varies per disease; separate models permit disease-specific threshold optimization.

### 2.3 Deterministic Knowledge Base for Specialty Mapping
- **Decision:** Specialty and equipment requirements are mapped via a transparent JSON knowledge base (`condition_specialty_map.json`) rather than end-to-end machine learning.
- **Rationale:** Mapping clinical diagnoses to hospital services (e.g., CKD $\to$ Nephrology + Dialysis Unit; STEMI $\to$ Cardiology + Cath Lab) is defined by clinical guidelines and hospital capability standards. A rule-based knowledge base eliminates AI hallucinations, guarantees deterministic routing, and is easily auditable by health authorities.

### 2.4 Recall-First Operating Thresholds ($\ge 90\%$ Sensitivity)
- **Decision:** All condition screening models tune operating thresholds specifically to guarantee out-of-fold recall/sensitivity $\ge 0.90$.
- **Rationale:** In clinical referral triage, the cost of a false negative (failing to identify an acute cardiac or renal patient) is catastrophic, whereas the cost of a false positive is minor (a licensed doctor reviews every recommendation). Tuning for sensitivity prioritizes patient safety.

### 2.5 Repeated Stratified Cross-Validation & Out-of-Fold Calibration
- **Decision:** 5-fold stratified cross-validation repeated 10 times (50 iterations) with Platt sigmoid calibration.
- **Rationale:** On modest benchmark datasets ($N \approx 300 - 3,100$), single train/test splits risk high variance and optimistic overestimation. Repeated CV yields stable probability calibration (Brier scores $< 0.18$) and robust 95% bootstrap confidence intervals.

## 4. How to Run

### 4.1 Prerequisites
Python 3.10+ with scikit-learn, joblib, pandas, numpy, pydantic, fastapi, uvicorn, and pytest.

### 4.2 Training Pipeline
```bash
# 1. Train Triage Severity Model (outputs triage_model.joblib & triage_model_card.json)
python ml/train_triage.py

# 2. Train Condition Screening Models (outputs 5 models & screening_summary.json)
python ml/train_screening_models.py

# 3. Export Clinician Review Cases
python ml/export_clinician_review_cases.py
```

### 4.3 Running the FastAPI Microservice
```bash
uvicorn ml.service.app:app --host 127.0.0.1 --port 8000 --reload
```
Interactive Swagger documentation is available at: `http://127.0.0.1:8000/docs`

### 4.4 Running Test Suites
```bash
# Python Service Tests
pytest ml/tests/test_service_endpoints.py

# Node.js Integration Tests
cd backend && npm test
```
